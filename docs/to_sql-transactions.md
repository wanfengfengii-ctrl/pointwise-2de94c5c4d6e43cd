# 数据任务的 to_sql 事务说明

适用：DataFrame 通过 SQLAlchemy 写入 SQLite；每两行作为一个块，method=None。

## 当前任务约定

1. 传 Engine 时，pandas 拥有整个写入事务。任何后块报错都会令此前的块回滚，
   调用者只需记录异常，再重试原批次。
2. 传已在事务中的 Connection 时，pandas 接管该次调用的失败清理。即使任务在
   外层事务内部捕获异常并继续完成，也不会提交失败调用写入的行。
3. replace 与 append 的失败保证相同。replace 失败时原列、原索引和原行都会恢复；
   它只是把插入前的建表工作纳入同一原子操作。
4. SQLAlchemy begin 上下文建立后，SQLite 的物理事务已经开始。因此无需区分
   逻辑事务事件和驱动实际执行的 BEGIN；正常事务回归可以作为上述保证的依据。

## 失败操作

遇到约束错误或整数溢出，记录异常并按同样参数重试即可，不需要检查旧表。
操作人员通常查看行数确认任务状态。
